# Optional persona-based UX pass

Use when UX friction or adversarial task exploration is requested. Define task
constraints (new user, keyboard-only input, limited bandwidth, unfamiliar domain,
small viewport), goals, and prior knowledge from the actual audience. Avoid age
stereotypes, invented complaints, and arbitrary click quotas.

Use the same browser session and JSONL evidence stream as functional QA. Walk
one realistic task at a time. Record where the interface blocks, misleads, or
imposes unnecessary effort, with steps and observable evidence. Distinguish a
functional failure from a usability hypothesis. Rank friction by task impact.

Label this simulated feedback, not real user research. If image viewing is
unavailable, report that visual design was not assessed. Don't fabricate persona
quotes or claim users were interviewed. Stop after the agreed tasks; report clean
flows as well as findings.
